# AFSIM 语法高亮需求规格说明

文件顶层下可包含配置块、脚本块、以及单行命令

## 块


所有形如：
```
XXX [YYY] [ZZZ] [...]
[...]
end_XXX
```
的块，XXX与end_XXX均需高亮为关键字，两者之间的所有内容均为块内容。

其中“execute、on_update、on_message、on_initialize、script、script_variables……”等块为脚本块，内部语法为C++，需调用VSCode已有的C++语法高亮器。
其余的为配置块，配置块内部可嵌套配置块作为子配置结构，也可以嵌套脚本块作为私有脚本或触发式的脚本。
部分配置块可附带定义类型名YYY，同时可以继承已有类型ZZZ。
配置块内部可含单行配置项，含配置项名、配置项值，有时会带有单位。
少数配置项如on、off仅出现配置项名。
部分配置项如edit、add、delete等为操作式配置项，它们对已有的配置做修改；如edit后紧跟着一个完整的配置块。

高亮单位时注意最长匹配，防止m优先于m/s的情况发生。
部分配置项与配置块关键字同名，如radar_signature。

## 命令

部分命令如include_once、end_time为仿真配置命令，单行完成。

## 高亮内容

块起始与结束关键字
命令关键字
配置项名
配置项值
数值
单位
常数名
脚本
aux_data块内部的int、double、string、bool四种类型变量定义
类型名与继承名

# AFSIM 自动补全需求规格说明

自动补全分为配置补全与脚本补全两大部分，需要区分各自上下文，不能混淆出现。
（注意后续提及的类型也分为配置类型（如WSF_PLATFORM）、脚本类型（如WsfPlatform））

## 配置补全

配置补全均为全局内容，不需要考虑是否为本文件以及include文件可达。
需要从json配置文件读取预定义的块关键字、类型名、配置项名等内容。
需要注意部分配置块不能嵌套出现在块内部，部分脚本块不能脱离配置块存在，脚本块内部不能嵌套出现脚本块。
当处于顶层时，仅出现配置块、脚本块与命令的补全。
当处于某个块的上下文中时，仅出现与该块类型相关的配置项补全以及非顶层的配置块、脚本块补全。（需要建立配置项与配置块的所属对应关系）
当填写完毕数值时，需要出现单位补全。
当填写完部分块起始与块名时，需要出现继承类型补全。
配置补全时，始终出现常数名补全。
aux_data块内部时，出现int、double、string、bool四种类型的补全。

## 脚本补全

脚本补全分全局与可达部分。
全局部分从json配置文件读取预定义的函数、类型、全局变量等内容。
可达部分指动态学习的，本文件以及include嵌套文件内部动态定义的内容。
常态下补全类型、函数、变量、控制语句关键字（for、while、break、continue、return等）。
在打出字母、“.”、“>”时触发补全。

# AFSIM 查找定义需求规格说明

在配置时，需要能够查找继承类型的定义。（非AFSIM预置类型，仅针对用户自定义基类型）

脚本块内部，需要能够查找变量、函数的定义。它们可能跨块、跨文件存在（如多个script块、配置块内的script_variables块可理解为类属性，本配置块内的script均可访问、include其它文件中的script等）。

# AFSIM 悬浮提示需求规格说明

仅在脚本块内部触发。
鼠标悬浮于变量时，显示其类型。
鼠标悬浮于函数时，显示其参数列表以及返回类型。（可通过显示其定义行实现）

# 注意事项

动态学习内容时需要考虑性能，中断编辑0.5s才进行更新。
部分需求阐述可能存在细节与矛盾问题，请你分辨并解决。
